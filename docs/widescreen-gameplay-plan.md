## 1. Define the result before changing code

Deliver two title-menu actions, **Play Arcade** and **Play Widescreen**. Arcade starts the existing 320×240 campaign. Widescreen starts a separate campaign session showing extra playable world on the horizontal axis at the same vertical scale. A submarine must be able to enter the added space, fire there, collide with terrain there, take damage there, and collect an item there. Both players share that world. Every encounter must remain winnable through ordinary input. A larger swap chain or a wider background alone cannot satisfy this contract.

Use the following design decisions as implementation defaults. The game still advances on its existing logic clock. Keep weapon speeds, damage, lifetimes, difficulty settings, vertical framing and authored stage order. Preserve encounters with a physical landmark at that landmark. Move an event tied to an edge of the picture according to the new edge. Document individual exceptions with a replay showing why the default fails. Keep Arcade as the first menu choice. Keep both modes available regardless of monitor aspect or CRT preset.

**Working order.** Complete steps 2–5 before converting actor handlers. Use one ordinary scrolling encounter as a vertical slice through steps 6–9. Prove one playable wing with effects off, then both wings with effects on. Apply the same method to every stage in step 10. Keep unfinished widescreen work out of public releases until step 12 passes.

## 3. Specify one coordinate contract

Keep five quantities explicit at call boundaries. They are the script progress coordinate used to advance ROM events, the world position of a physical object, the camera origin, the signed picture coordinate, and the destination pixel on the monitor. Also identify hardware sprite-list coordinates, layer scroll coordinates, fixed-point fractions, and HUD coordinates wherever they enter or leave these spaces. Write down the actual transform for one submarine, one tile and one sprite by logging all values in the same tick. Several original actor fields already include scrolling or a hardware bias. Adding the camera again will produce double motion.

Use square game-pixel units and 240 units of visible height. Exact wide width is 240 × 16 / 9 = 426⅔ units. A practical design is a **428×240 working raster** with a centered visible aperture of 426⅔ units. Its sides each have ⅔ unit of overscan. At 3×, rasterize or present 1284×720 and crop two output pixels per side to obtain exactly 1280×720. For other sizes map destination pixel centers into the same rational aperture. Clip texture filtering to valid texels. Use an exact 16:9 destination rectangle wherever the monitor permits, centering bars outside it on other displays. Minimize rounding error at odd window sizes. Never feed monitor dimensions back into simulation.

Use the legacy picture origin as a convenient reference in the interior of a level. Arcade covers [0,320). The wide working raster there covers legacy X in [−54,374), so raster X = legacy X + 54. Reproduce the original 320 columns by selecting wide working columns 54 through 373 inclusive with the same camera and world state. Use signed intermediates and half-open intervals. Overscan samples are available for filtering. Size player limits by their hull against the **visible** edges, rounding inward. At a level boundary choose the camera origin using measured authored map limits. Keep script progress separate when clamping would otherwise move an encounter. Put these calculations and tests in one small view description; pass it explicitly to subsystems or through the existing session owner.

**Geometry unit tests.** Verify the endpoints, center, first and last visible pixel centers, a negative legacy X, both seam neighbors, and an object whose center is just outside while one pixel is visible. Convert world → raster → world at fixed camera, including subpixel scrolling. At 1280×720 an unscaled 16×16 game tile must occupy 48×48 output pixels on an aligned interior sample. Compare the center against Arcade only at an identical state, before HUD relayout and display filtering. Independently check both wings against known map addresses and world objects. A centered Arcade frame with empty borders passes only the center test.

## 11. Diagnose failures from the first divergent tick

| Symptom | Trace and repair |
|---|---|
| Widescreen looks plausible but plays like 4:3 | Place an actor wholly beyond old X=319 and put P2 in the same wing. Log player proposed/accepted X, source pixel, shot candidate, hit and score. The first owner still using the old edge determines the fix. Repeat on the left with negative legacy X. |
| Blank strip, repeated seabed or a wall you can swim through | Freeze the camera. Log expected world cell → decoded stage source → resident tile → displayed pen and probe attribute. Distinguish missing source data, stale cache, unsigned wrap and inconsistent collision lookup. Fix the earliest mismatch and retest after scrolling away and returning. |
| Enemy pops in, fires invisibly or appears twice | Compare readiness, consumed-row cursor, allocation ID/generation, draw bounds, attack-enable tick and intended entry. Fix readiness/arming or extent clipping at the responsible stage; reproduce after a full pool retry and a restore. |
| A boss cannot be hit from a wing | Overlay weapon path, target list, hurtbox, invulnerability, parent offset and phase. Fire the same eligible weapon in center and wing. Correct the failed coordinate/list lookup and verify an armored hit still fails. |
| Boss never spawns or camera remains locked | Trace previous/current script progress, signed compare, pending row, pool availability, parent/child completion and lock owner from the last good tick. Repair the missing crossing/retry/notification. Recheck fast crossing, slow crossing, pause on equality and simultaneous deaths. |
| Only smooth mode shows detached sprites or lights | Record simulation and presentation timestamps with camera samples for world, sprites and emitters. Align all visual layers to the same sample and discard history after discontinuities. Verify exact mode and both screen edges. |
| A change breaks Arcade | Replay the earliest divergent tick against the baseline. Compare mode initialization, integer casts/wrap, lookup indices and ordering. Restore the original Arcade calculation at its owner or move wide-only behavior behind the session mode. Rerun the same recording before continuing. |

For any new failure, keep the smallest input journal that reproduces it, the tick before/after, expected result, actual values and source owner. Establish a failing assertion first. After the repair, rerun that case, its opposite edge, the affected stage and the Arcade regression. Never “fix” a failing test by increasing a timeout until it passes; demonstrate forward progress with a changed camera, consumed row, successful damage event or completed phase.

## 12. Qualification and completion checklist

1. **Arcade parity.** Under identical inputs/configuration, compare the unmodified and candidate Arcade executables at each logic pass for the deterministic state captured in step 2, including event order and board holds. Compare canonical unfiltered gameplay pictures and separately check menu changes. Preserve the existing reference and report the first difference. 2. **Independent wide proof.** Save raw and final pictures with aperture coordinates, stage identity and source hash. At a fixed interior camera, verify the center crop plus independently calculated wing samples. Demonstrate genuine world interaction outside each original edge in normal input footage and traces. Run deliberate negative controls in a test build: restore a 320 clip, shift collision probes one tile, or stretch an Arcade frame. Each corresponding test must fail, then pass on the actual build.
3. **Coverage and campaigns.** Require all six stage cards, every reachable entity/placement and every boss phase linked to passing evidence; include player-count/difficulty gated variants. Require uninterrupted menu-to-ending clears in Wide solo and local co-op, ordinary-input evidence for both endings, and comparable Arcade clears. 4. **Presentation and controls.** Exercise both public menu actions with keyboard and gamepad; switch between modes in one process. Check software and GPU paths, exact and smooth scrolling, windowed/fullscreen, supported scaling, CRT on/off and enhancements on/off. 5. **Evidence receipt.** For each case record build hash, mode, stage/row/handler, initial conditions, input/checkpoint identity, expected assertions, measured values, exit/ending reached and capture/trace paths. Preserve failures with their passing reruns. Summarize rows as passed, failed, untested or proven unreachable. Finish only with zero unexplained Arcade regressions, zero untested reachable behaviors and zero unresolved visual, collision, combat or progression failures in the supported matrix.
